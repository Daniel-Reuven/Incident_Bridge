About Incident Bridge

An internal web system for logging, prioritizing and tracking an organization's IT incidents — so routine maintenance is never skipped or done out of order, and the most severe faults are always handled first.

The team

    What it does

    • Maintenance queue — routine tasks are done one at a time, strictly in the order they were reported.
    • Fault queue — faults of every severity share one priority queue, so a Critical fault is always taken before a Major or Minor one. The severity is worked out from four questions asked when the fault is reported.
    • A full history — every update and every status change is kept with who made it and why, including why an incident was closed.
    • AI analysis — anyone can ask an AI model (Gemini, Claude or OpenAI) to read a fault and its updates; the answer is posted back as a comment.
    • Site portal — admins monitor the organization's websites, see which open incidents concern which site, and notify the right mailing lists when a site has a problem.
    • Live updates — every open page updates the moment anyone changes something.

    New here? The Guide explains how to use it, for users and admins.

    How it is built

    • Backend: Python with FastAPI; data kept in SQLite.
    • Frontend: plain HTML, CSS and JavaScript, served by the same app.
    • Queues: a deque for the maintenance queue (first in, first out) and a heapq priority queue for faults.
    • Live updates: Server-Sent Events.
    • AI analysis: one dedicated background thread works through the requests one at a time, using each company's official Python SDK.
    • Quality: an automated test suite runs on every change (GitHub Actions).

    The full design — the object model, the data structures and why each was chosen — is in the project's README.

    Use of AI in building it

    The team designed and built Incident Bridge. An AI assistant (Claude, by Anthropic) helped review the code, write documentation and generate the sample data; every suggestion was tested and reviewed before it was kept. The details are in AI_USAGE.md in the repository.
